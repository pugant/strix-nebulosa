# Patches

Every feature of this lab is carried as a `git am`-clean series under [`patches/`](patches/) — but you rarely need to apply anything: the [`rocmfpx/`](rocmfpx/) snapshot **already contains every merged series** (it is the fork at `7d54c4bd2`, buildable as-is — see the [README build section](README.md#build)). The patches exist to read the history, cherry-pick a single feature, or re-create a branch.

Apply notes — the non-obvious ones:

- Every series applies with `git am` onto the **fork base named in the Base column** (the fork is [charlie12345/ROCmFPX](https://github.com/charlie12345/ROCmFPX), a fork of [ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp); a series whose base is "fork `main`" will not apply on ggml-org master).
- [`patches/drafter-routing/0001-drafter-routing-mtp-dflash-per-request.patch`](patches/drafter-routing/0001-drafter-routing-mtp-dflash-per-request.patch) is **one file containing the full 14-commit series** — `git am` splits it back into its 14 commits.

- [`patches/optim-w2-series/`](patches/optim-w2-series/) applied on the tree of `e2f46e0e2` reproduces the **tree** of `27c93938d` (verified: `git am` on a clean worktree at the campaign marker, 3× Applying, zero conflicts). The wave-2 optimization campaign measured on the FP2MIX v2 model (see `docs/optim/CAMPAIGN-BASELINE-W2.md` and `ROADMAP-ROI-W2.md` in the engine workspace): (1) int-dot MMVQ for small-k decode on AMD — tg512 +9.4%, tg128 +15.8% (FP2MIX; neutral on the FP4 LEAN: per-quant-family); (2) 64MB loader staging on the buffered path — cold load −4.3%; (3) QSA-decode mask-opt — exact-by-construction block skip (neutral-at-worst measured; kept as free). Two measured NO-GOs close their threads: rocWMMA flash-attention on gfx1151 regresses pp32768 by 54% (the WMMA kernel compiles and runs — it is just 2.2× slower than the scalar TILE path), and CCD pinning does not move VK variance in this protocol.
- [`patches/optim-w3-series/`](patches/optim-w3-series/) applied on the tree of `27c93938d` reproduces the **tree** of `65084bd1c` (verified: `git am` on a clean detached worktree, zero conflicts). The wave-3 campaign ran on the FP4 LEAN production model: (1) **TOPK-QSA-GPU** — extends the Vulkan `top_k` beyond k=1024 (the qwen4exp QSA indexer asks k=2051 at 32k context) via single-workgroup n-ary search with global-memory bucket counting; the k≤1023 path is byte-identical. Measured on the LEAN FP4: combined32k **+17.96%**, pp32768 **+16.60%**, combined16k +19.03%; ppl within ±0.16% both corpora; graph splits 28→6 same-config; GPU-vs-CPU equivalence 4/4. The two-stage merge sketch was proven impossible for exact top-k with k>2^10 (workgroup emission cap) — the threshold/istogramma variant of the original proposal was implemented instead. (2) The DRAFTER-FAST card (ROCmFP4-FAST drafter) closed NO-GO: throughput identical (Δ+0.05 tok/s vs threshold 1.07) with acceptance 0.8626 vs 0.8481 — the draft was never the bottleneck; not deployed.
- [`patches/optim-w4-series/`](patches/optim-w4-series/) applied on the tree of `65084bd1c` reproduces the **tree** of `ff264cbc5` (verified: `git am` on a clean detached worktree, zero conflicts; the `rocmfpx/` snapshot adds only the wave-4 `AI_CHANGES.md` session entry). The wave-4 campaign went after the prefill GEMM stack — one GO deployed: **small-m split-k** (patch 0006 + the default flip in 0008), measured interleaved pp8192 **+3.95%** / combined32k **+2.33%** on the LEAN FP4 with ppl improved and the output battery clean (seed-retry shows the one DANTE-2 failure basin exists in the unpatched baseline too — see the [wave-4 note](docs/experiments/2026-09-08-vulkan-optimization-wave4.md)). Four measured NO-GOs close their threads: pooled indexer keys (tap cost = the gather it saves), int-dot MMQ pipelines (never instantiated on RADV, and slower by 8-33% when forced on — patch 0003 also fixes a latent warptile bug, garbage for m>32, with 15 regression cases), f16 FA accumulator on quantized KV (near-tie degenerate output), element-wise fusion batch (below the async-submit floor; dropped from the deploy branch, full history on the engine's `optim-w4-full` branch).
- [`patches/optim-w5-series/`](patches/optim-w5-series/) applied on the tree of `286f51d4b` reproduces the **tree** of `e8a4d8c5f` (verified: `git am` on a clean detached worktree, zero conflicts; the `rocmfpx/` snapshot adds only the wave-5 `AI_CHANGES.md` session entry). The wave-5 campaign ran roofline-first — three wall-critical probes decided the cards before any implementation, ~7 GPU-minutes vs 35 planned. One GO deployed: **T23-CRC**, the `--cache-disk-persist` restore CRC32 moved from the 256-entry byte-wise table (0.63 GB/s) to a bit-exact PCLMUL fold (16 B/iter, same polynomial, **12.9×**, 8.07 GB/s) with runtime dispatch and the table as verbatim fallback — the canonical restore entry is 2,272,282,732 B and CRC is 69.8% of the real restore wall (the historical 1.57 s figure was `load_ms` without CRC), so the expected restore drop is −64% (end-to-end timing provisional at the next π turn). Host-only series (`src/llama-persist-meta.cpp` alone): final A/B −1.2% inside the baseline's own 2.4% spread with spec acceptance identical, per-probe battery shas bit-identical 12/12, harness evidence on 14 real production entries; deployed 2026-09-09 as `qwen4exp-mtp-vk-optim-w5`, no new flags. Two threads closed by measurement in the [wave-5 note](docs/experiments/2026-09-09-vulkan-optimization-wave5.md): FA-PP-TILE is a **structural NO-GO** (coopmat2 is absent on gfx1151/RADV — every FA call runs COOPMAT1 with Br16/Bc64 hardcoded; the correct Br32 dual-panel halves KV rereads but LDS 25,968→42,672 B/WG drops occupancy 2→1 WG/CU and loses on every FA shape, c32k −5.96%; dropped commits preserved on the engine's `optim-w5-full` branch), and host sampling is 0.32% of the round wall (closed in the F0 probe, no card).

- [`patches/optim-w7-series/`](patches/optim-w7-series/) applied on the tree of `f37da5c0c` reproduces the **tree** of `b21239c06` (verified: `git am` on a clean detached worktree, 15/15 Applying, zero conflicts). The wave-7 campaign ran honest-gated on the FP4 LEAN: **one speed GO — the MoE router requant** (per-tensor gating `--pure`+`--tensor-type` in the quantizer, then the deployed trunk gets 48× `ffn_gate_inp` F32→Q4_0_ROCMFP4: router path 240.47→34.22 MiB/forward = 7.03×, ppl en −0.27% / it +0.37%, c32k +4.24%, battery 12/12 bit-identical). The **FR-Spec d2t draft-vocab trim closed as a speed NO-GO with the lossless port kept in the engine** (65k trim: acceptance 0.88× on thinking-heavy workloads; 128k: acceptance 1.049× but head bytes at parity by construction). Also in: allocation-free BPE session (tokenize 1.80×, π path e2e ~20 ms, bit-identity 16/16), k-slot graph-result cache rev-2 (opt-in, default OFF — one workload still thrashes, keyed-eviction follow-up parked), and bit-exact EW fusions active on VK. Final interleaved A/B +3.9% (deployed 2026-09-11 as `qwen4exp-mtp-vk-optim-w7` on explicit user GO below the +5% gate, park RAM mirror on). ## The 9-patch `spec-cache-trailing-rollback` series

Breakdown of [`patches/spec-cache-trailing-rollback/`](patches/spec-cache-trailing-rollback/):

- `0001` + `0003` — bounded trailing rollback at the spec boundary (**merged upstream** via [charlie12345/ROCmFPX#69](https://github.com/charlie12345/ROCmFPX/pull/69))
- `0002` — checkpoint-based rollback for the spec-boundary cache
- `0004` — push all batch/verify rows into the MTP boundary state
- `0005` — forced-end sequence prefixed with a newline, for cache round-trip
- `0006` — accept `thinking_token_budget` (vLLM name) as an alias
- `0007` — checkpoint-based salvage (the ~91% prefill figure)
- `0008` — accept `reasoning_budget_message` per request (OpenAI-compat)
- `0009` — newline between wrap-up message and end tag
